# 关于"脱壳"的科普与项目实际能力说明

## 📚 什么是"脱壳"？

### 基本概念

**脱壳（Unpacking）** 在软件逆向工程中指的是：
- 移除程序的保护层（壳）
- 恢复原始代码/数据
- 让加密/混淆的代码变得可读

### 常见的"壳"类型

#### 1. 加壳软件（传统意义）
```
原始程序 → 加壳工具（UPX/VMProtect/Themida）→ 加壳后程序
特点：
- 运行时解密
- 反调试
- 代码混淆
- 完整性检查
```

#### 2. Java/Minecraft 的"壳"
```
Java 程序的保护层：
1. 代码混淆（Obfuscation）
   - 类名：net.minecraft.client.Minecraft → a.b.c
   - 方法名：getTick() → a()
   - 字段名：player → b
   
2. 字符串加密
   - "Hello" → 加密字符串 → 运行时解密
   
3. 控制流混淆
   - 正常流程 → 跳转/条件混乱 → 难以阅读
   
4. 自定义 ClassLoader
   - 自定义类加载逻辑
   - 运行时解密/转换类
```

## 🎯 本项目实际能做什么？

### ✅ 可以做的（已实现）

#### 1. Runtime 信息采集
```java
// 通过 Instrumentation API
Class<?>[] classes = instrumentation.getAllLoadedClasses();

// 获取所有已加载的类
for (Class<?> clazz : classes) {
    System.out.println(clazz.getName());
    // 输出: net.minecraft.client.Minecraft 或 a.b.c
}
```

**能力**：
- ✅ 列出所有运行时加载的类
- ✅ 获取类的真实名称（混淆后的）
- ✅ 分析 ClassLoader 结构
- ✅ 探测加载顺序

#### 2. 识别混淆类型
```
检测依据：
- 类名特征: a.b.c → Mojang 混淆
- 类名特征: class_123 → Yarn 映射
- 包名: com.netease → 网易自定义
```

**能力**：
- ✅ 判断是否混淆
- ✅ 识别混淆工具
- ⚠️ 但不能自动还原

#### 3. ClassLoader 分析
```
ClassLoader 层次结构：
Bootstrap
  └─ Platform
      └─ App
          └─ NetEaseCustom ← 网易自定义
```

**能力**：
- ✅ 枚举所有 ClassLoader
- ✅ 找到加载 Minecraft 类的 ClassLoader
- ✅ 为后续 Bridge 设计提供信息

---

### ⚠️ 不能做的（误解澄清）

#### ❌ 不能自动还原混淆
```
混淆的类名: a.b.c
期望: net.minecraft.client.Minecraft
实际: 需要建立 Mapping（映射表）
```

**为什么不能？**
- 混淆是单向的
- 语义信息已丢失
- 需要通过特征匹配或现成 Mapping

#### ❌ 不能绕过反调试（本项目未涉及）
```
如果网易 MC 有反调试：
- 检测 Attach
- 检测 Instrumentation
- 完整性校验

本项目：
- 使用标准 Java API
- 不主动绕过保护
- 如果被检测，会失败
```

#### ❌ 不能"脱壳"加密的 JAR
```
如果网易 MC JAR 是加密的：
- 文件加密: 无法直接读取
- 运行时解密: 需要在内存中捕获

本项目：
- 只在 JVM 运行时工作
- 不处理磁盘上的加密文件
```

## 🔍 本项目的"脱壳"实际上是什么？

### 准确的说法

**Runtime 分析 & Class Dump**

#### Phase 1（当前）
```
功能: 只读分析
- 读取运行时已加载的类
- 分析 ClassLoader 结构
- 识别混淆类型
- 生成分析报告

不做:
- 不修改字节码
- 不还原混淆
- 不绕过保护
```

#### Phase 2（计划）
```
功能: 建立 Bridge
- 通过特征识别关键类
- 建立 Mapping（如果混淆）
- 反射访问 Minecraft API
- 实现事件监听

示例:
混淆类 a.b.c → 特征: 单例 + 持有 Window
         → 判断: MinecraftClient
         → Mapping: a.b.c = MinecraftClient
```

## 💡 真实的"脱壳"过程（如果需要）

### 如果网易真的加了保护

#### 步骤 1: 运行时 Dump
```java
// 使用 Instrumentation
instrumentation.addTransformer(new ClassFileTransformer() {
    @Override
    public byte[] transform(ClassLoader loader, String className, 
                          Class<?> classBeingRedefined, 
                          ProtectionDomain protectionDomain, 
                          byte[] classfileBuffer) {
        // 保存原始字节码
        saveToFile(className, classfileBuffer);
        return null;  // 不修改
    }
}, true);

// 触发重转换
instrumentation.retransformClasses(targetClass);
```

**结果**: 获得内存中的字节码（已解密/解混淆后的）

#### 步骤 2: 反编译
```bash
# 使用 CFR/Fernflower/Procyon
java -jar cfr.jar dumped-class.class --outputdir src/
```

**结果**: Java 源码（但类名仍是混淆的）

#### 步骤 3: 建立 Mapping
```
方法 1: 手动分析
- 通过代码逻辑推断
- 单例 → MinecraftClient
- 持有 Window → MinecraftClient

方法 2: 特征匹配
- 字段类型、数量
- 方法签名
- 调用关系

方法 3: 使用现成 Mapping
- MCP Mapping (Forge)
- Yarn Mapping (Fabric)
```

#### 步骤 4: 重命名
```
a.b.c → net.minecraft.client.Minecraft
a.b.d → net.minecraft.client.player.LocalPlayer
...
```

## 🎓 总结

### 本项目的"脱壳"

**实际上是**：
- Runtime 信息采集
- ClassLoader 结构分析
- 混淆类型识别
- 为后续开发 Mod 做准备

**不是**：
- 传统意义的脱壳
- 自动还原混淆
- 绕过所有保护

### 核心价值

1. **了解 Runtime 结构** - 知己知彼
2. **为 Mod 开发铺路** - 知道如何访问游戏 API
3. **学习逆向技术** - 理解 Java 程序保护

### 实测的重要性

**所有假设都需要验证**：
- 网易是否真的混淆？
- 混淆程度如何？
- 是否有反调试？
- 能否成功注入？

**只有实测后才能确定下一步方向。**
