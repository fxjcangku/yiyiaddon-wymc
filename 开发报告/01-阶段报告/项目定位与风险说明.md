# YiYi WYMC Loader - 项目定位与风险说明

**项目类型**: Minecraft 辅助工具开发框架  
**目标用户**: 开发者、玩家  
**更新时间**: 2024-09-24

---

## 🎯 项目定位

### 不是什么
- ❌ 不是传统意义的"外挂"（自动瞄准、透视等）
- ❌ 不是破解工具
- ❌ 不是商业产品

### 是什么
- ✅ **Minecraft 辅助 Mod 开发框架**
- ✅ **类似 Fabric Loader，但专为网易 MC 设计**
- ✅ **提供建筑、生存等辅助功能**

---

## 📦 计划功能分类

### Phase 2 - 基础 Runtime
```
MinecraftBridge - 游戏 API 访问
EventBus - 事件系统
ModuleManager - 功能模块管理

风险等级: 低（仅框架，不实现具体功能）
```

### Phase 3 - 辅助功能

#### 🟢 低风险功能
```
✓ 信息显示
  - HUD（血量、坐标、FPS）
  - 小地图
  - 光照等级显示
  - 史莱姆区块显示

✓ 视觉增强
  - 高亮矿物
  - 实体 ESP（显示位置）
  - 夜视效果

风险: 极低，大部分服务器允许
```

#### 🟡 中风险功能
```
✓ 建筑辅助
  - 投影显示（Litematica 类似）
  - 自动整理背包
  - 路径规划显示
  - 方块放置预览

✓ 效率工具
  - 自动钓鱼（需要实际操作）
  - 自动挖矿提示
  - 农场收割提示

风险: 中等，部分服务器可能禁止
建议: 单人模式或允许的服务器
```

#### 🔴 高风险功能
```
⚠ 自动化操作
  - Printer（自动建造）
  - 自动战斗
  - 自动农场
  - 飞行/加速

风险: 高，容易被检测
建议: 仅单人模式，谨慎使用
```

## ⚖️ 风险等级说明

### 🟢 低风险（信息显示类）
```
特点:
- 只读游戏数据
- 不自动操作
- 不影响其他玩家

例子:
- HUD 显示
- 小地图
- 矿物高亮

被封概率: <5%
适用场景: 大部分场景
```

### 🟡 中风险（半自动辅助）
```
特点:
- 显示辅助信息
- 需要手动操作
- 提高效率但不完全自动

例子:
- 建筑投影
- 路径规划
- 背包整理

被封概率: 10-30%（取决于服务器）
适用场景: 单人/允许的服务器
```

### 🔴 高风险（全自动操作）
```
特点:
- 自动执行操作
- 明显违反公平性
- 破坏游戏平衡

例子:
- 自动建造
- 自动战斗
- 飞行/加速

被封概率: 60-90%
适用场景: 仅建议单人模式
```

---

## 🛡️ 如何降低风险

### 开发阶段
1. **使用测试账号**
   - 不要用主号测试
   - 准备 2-3 个小号

2. **单人模式优先**
   - 先在单人世界测试
   - 确认稳定后再联机

3. **渐进式测试**
   ```
   第一步: 只加载 Agent，不运行功能
   第二步: 加载信息显示功能
   第三步: 加载辅助功能
   第四步: 测试自动化功能（谨慎）
   ```

### 实际使用
1. **了解服务器规则**
   - 部分服务器允许辅助 Mod
   - 部分服务器严禁任何修改
   - 加入前先咨询管理员

2. **低调使用**
   - 不要炫耀
   - 不要大规模传播
   - 避免影响其他玩家体验

3. **功能选择**
   ```
   推荐: 信息显示类功能
   谨慎: 半自动辅助功能
   避免: 全自动操作（联机时）
   ```

4. **应对检测**
   - 随时准备被封号
   - 不要投入太多时间/金钱在使用辅助的账号上
   - 保持备用账号

## 📊 社区对比

### Fabric/Forge Mod 生态
```
允许范围:
✓ 客户端优化 (OptiFine, Sodium)
✓ 小地图 (JourneyMap, Xaero's)
✓ 信息显示 (HWYLA, WTHIT)
✓ 建筑辅助 (Litematica, Schematica)
✓ 背包管理 (Inventory Tweaks)

禁止范围:
✗ 飞行/加速
✗ X-Ray（透视）
✗ Kill Aura（自动攻击）
✗ Reach Hack（距离修改）
```

### 网易 MC 服务器
```
情况: 各服务器规则不同

严格服务器:
- 禁止任何客户端修改
- 使用即封

宽松服务器:
- 允许信息显示类
- 允许建筑辅助
- 禁止自动操作

单人模式:
- 无限制
- 推荐主要使用场景
```

## 💡 推荐使用方式

### 开发者
```
1. Phase 1: 分析 Runtime（安全）
2. Phase 2: 开发 Bridge 和事件系统（安全）
3. Phase 3: 先实现低风险功能
4. 逐步测试，记录反馈
```

```
1. 了解风险
2. 小号测试
3. 单人模式优先
4. 联机前确认服务器规则
5. 只使用信息显示类功能（最安全）
```
